# gorebob.com과 jaban.co.kr 제작 및 운영 계획안

작성일: 2026-10-03, Asia/Seoul. 상태: 검토용 제안. 대상: 사업 책임자, 제조·품질 담당, 영업·CS 담당, 콘텐츠 담당, 웹 개발 담당.

두 사이트는 하나의 고객 경험을 제공하되 역할을 나눈다. `jaban.co.kr`은 회사와 제품에 대한 신뢰, 선택·조리 지원, 상담을 담당하고, `gorebob.com`은 실제 상품 선택과 구매·재구매를 담당한다. 초기에는 워드프레스 콘텐츠 사이트와 기존 카페24 구매 화면을 안정적으로 연결하고, 계산기와 발주 도구는 실제 상품 데이터 및 운영 수요를 확인한 뒤 추가하는 방안을 권고한다.

이 문서는 제작 범위, 화면과 콘텐츠, 데이터 연결, 일정, 담당, 비용 산정, 공개 조건, 반복 운영과 성과 평가를 정한다. 일정·제작량·인력 시간·수치 목표는 제안이며 승인된 계약이나 확정된 사업 목표가 아니다. 호스팅 계약, DNS 변경, 운영 배포, 고객 연락, 유료 결제는 실행하지 않았다.

### 홈 화면 구성

1. 상단에 로고, 간결한 메뉴, 검색, 고래밥 쇼핑몰 버튼을 배치한다.
2. 첫 화면에서 회사가 제공하는 제품과 도움을 설명하고 제품 알아보기·쇼핑몰 구매·거래 상담을 표시한다.
3. 급식·외식·가정용 고객이 자신에게 맞는 안내를 고를 수 있게 한다.
4. 가공 방식·규격 비교와 실제 제조 사진·영상을 제공한다.
5. 검토된 레시피와 영상, 자주 묻는 질문을 노출한다.
6. 회사·품질 설명과 문의를 배치하고 실제 운영 정보를 하단에 표시한다.

모바일은 정보 한 묶음을 한 열로 읽도록 하고, 영상은 사용자가 선택해 재생한다. 콘텐츠 상세에는 글과 직접 관련된 상품 1~3개를 제안하되 실제 연결 확인이 끝난 상품만 게시한다.

### 디자인과 편집 기준

브랜드 로고·색상·서체는 사용 권한과 기존 자산을 확인한 뒤 공통 규칙으로 정리한다. jaban에서는 설명과 사진을 충분히 제공하고 gorebob에서는 옵션·가격·수량·배송 정보가 쉽게 보이도록 한다. 한국어 본문 크기, 줄 간격, 버튼 대비, 키보드 이동, 이미지 대체텍스트, 문의 오류 표시를 함께 검토한다.

운영자는 워드프레스 편집 화면에서 글·사진·관련 링크를 바꿀 수 있어야 한다. 자주 반복하는 가이드·레시피·FAQ 구조는 편집 양식으로 제공하고, 코드 수정이 필요한 요소는 최소화한다.

### P1 빠른 발주 화면

실제 급식 또는 업소용 상품을 고객이 반복 주문하기 좋은 목록으로 구성한다. 한 행에 상품명, 옵션·규격, 실제 판매 단위, 적용 가격, 판매 개수, 구매 총량, 상품금액, 판매상태를 표시한다. 모든 제품을 일괄 5kg로 처리하지 않는다.

고객이 여러 행을 선택하고 수량을 입력한 뒤 선택 내용을 검토하도록 한다. 카페24에서 지원하는 연결 방법을 시험 환경에서 확인한 후 표준 장바구니에 반영한다. 단순 링크 단계에서는 자동 담기를 약속하지 않는다. 일부 상품만 추가되면 성공·실패한 행을 구분하고 재시도 시 중복 추가를 방지한다.

### P1 재주문과 저장 목록

기존 재주문 구현이 현재 정상이라면 재사용을 우선한다. 과거 주문의 상품·옵션·개수를 현재 판매 정보와 대조하고, 삭제·품절·옵션 변경·가격 변경·판매 단위 변경을 각각 표시한다. 과거 수량이 의미하는 중량을 지금의 개수로 조용히 바꾸지 않고 고객 검토를 받는다.

저장 목록은 실제 요구가 확인되면 추가한다. 개인 목록은 카페24 로그인 및 서버 권한 확인을 기반으로 설계하며, 타인의 목록·주문을 볼 수 없는지 검증한다. 브라우저 임시 저장만 제공한다면 기기 변경 시 보존되지 않는 특성을 안내한다. 저장 목록 구현을 위해 jaban에 별도 구매 회원을 먼저 만들지 않는다.

콘텐츠 담당이 질문과 원본을 모아 초안을 작성하고, 제조·품질 담당이 사실·규격·공정 표현을 확인한다. 영업·CS 담당이 구매 조건·문의 연결을 검토하고 운영 총괄이 공개 범위를 확정한다. 게시 후 모바일·사진·링크를 확인하며, 제품 변경이나 자료 만료가 발생하면 영향을 받는 글과 다운로드 자료를 함께 수정한다.

### 연동을 세 단계로 구현

1. **P0 링크 연결:** 콘텐츠에서 검증된 상품·분류로 이동한다. API 장애가 콘텐츠 열람을 막지 않도록 한다.
2. **P1 상품 조회:** 기존 인증 체계가 제공할 수 있는 공개용 응답과 서버 접근을 확인한 뒤 실제 상품 정보가 필요한 도구에 사용한다. 갱신 시각·오류·최신성 기준을 정의한다.
3. **P1 이후 구매 초안 전달:** 수량·옵션을 검토용 초안으로 전달하고 gorebob에서 재검증한다. 자동 장바구니 반영은 지원 방식과 로그인 상태를 검증한 기능에만 제공한다.

카페24 공식 안내는 관리자용 Admin API와 고객 화면용 Front API를 구분한다. 구현에 사용할 API·스코프·버전·호출 한도는 기존 연동 담당과 확인한다. OAuth와 관리자 토큰은 기존 `JABAN_AGENT` 연동에서 관리하며 브라우저·워드프레스 공개 파일에 넣지 않는다. 기존 연동에 변경이 필요하면 별도 업무 범위로 남긴다. [카페24 API 공식 안내](https://apidocs.cafe24.com/en/docs/guide/intro)

API 오류·응답 지연·품절·옵션 삭제 시 확정 가격이나 주문 완료를 표시하지 않는다. 상품 상세에서 확인하도록 연결하고, 도구의 가격 조회 실패와 콘텐츠 열람 실패를 구분한다. 상품 응답은 필요한 공개 필드만 사용하고 회원별 가격·개인정보가 공용 캐시에 섞이지 않도록 한다.

## 9 P1 계산기와 발주량 검증

입력값은 식수, 사용자가 정한 1인 원재료 정량, 선택 제품·옵션으로 시작한다. 단위는 식수는 명, 정량은 g, 중량은 kg, 주문 수량은 판매 개수로 구분한다. 세트·낱개·혼합 포장처럼 단순 중량 환산이 맞지 않는 옵션은 별도 규칙을 검증하기 전 지원하지 않는다.

- 필요 원재료량 kg = 식수 × 1인 원재료 정량 g ÷ 1,000
- 판매 개수 = 올림(필요 원재료량 ÷ 해당 옵션 1개의 판매 중량)
- 실제 구매량 kg = 판매 개수 × 해당 옵션 1개의 판매 중량
- 예상 상품금액 = 현재 적용 가능한 옵션 1개 가격 × 판매 개수

판매 개수는 최소 주문 수량·주문 배수·상한·재고 조건도 만족해야 한다. 중량이나 가격이 확인되지 않으면 해당 결과를 산출하지 않는다. 회원 할인·배송비·쿠폰이 미반영된 결과는 예상 상품금액으로 표시하고 최종 결제금액은 카페24에서 확인하게 한다.

예시를 사용한다면 시연 값이라고 명시한다. 조리 후 정량에서 역산할 때는 해당 제품·조리 조건에 대해 확인된 수율이 있을 때만 계산한다. 근거가 없으면 원재료 기준 입력으로 안내한다.

완료 조건은 산식 표시, 입력 단위·가정·가격 기준 시각 표시, 실제 상품 옵션 일치, 판매 개수와 장바구니 개수 대조, 반올림·최소 수량·품절·음수·빈 입력·과도한 값·조회 실패 처리이다. 계산기 검증이 끝나기 전 구매 자동 연결을 제공하지 않는다.

## 10 기술 구성과 호스팅 준비

### 워드프레스 구성 제안

표준 편집 기능을 활용한 맞춤 테마를 우선 검토한다. 선택한 기반 테마를 확장할 경우 자식 테마를 사용하고, 화면 표현은 테마, 콘텐츠 유형·상품 연결·도구는 맞춤 플러그인에 둔다. 초기에는 블록 편집기로 관리 가능한 페이지와 게시물을 사용하고 자료량이 늘면 가이드·레시피·영상 등 필요한 콘텐츠 유형을 분리한다.

워드프레스 공식 문서는 맞춤 콘텐츠 유형을 테마보다 플러그인에 두도록 권고한다. 이를 따라 테마 변경 후에도 콘텐츠 구조가 유지되게 설계한다. [워드프레스 콘텐츠 유형 공식 문서](https://developer.wordpress.org/plugins/post-types/registering-custom-post-types/)

폼·검색·SEO·백업 등 추가 기능은 기본 기능과 호스팅 제공 범위를 먼저 확인한다. 플러그인은 사용 목적, 유지보수 상태, PHP·워드프레스 호환성, 충돌, 연간 비용을 검토한 뒤 선택한다. 동일 기능을 여러 플러그인으로 중복 구현하지 않는다.

## 11 문의와 샘플 운영

### 문의 접수

문의 화면에서 제품·자료·맞춤 가공·거래 상담과 기존 주문 CS를 구분한다. 기존 주문 문제는 gorebob의 비공개 CS로 안내한다. 초기 상담은 시설·업종, 관심 제품·가공 형태, 희망 사용일, 회신 연락처, 문의 내용을 중심으로 받고 식수·정량은 필요한 경우 선택 입력으로 둔다.

공개 첨부 업로드와 주민등록번호·결제정보 등은 초기 문의에 필요하지 않다. 처리 목적·접근 담당·보존·삭제 기준과 실제 사업체의 개인정보 안내를 운영 담당이 확인한 뒤 적용한다. 문의 접수와 마케팅 수신 선택은 구분한다.

비공개 기록은 접수 → 담당 배정 → 1차 답변 → 추가 확인 → 견적 또는 상품 안내 → 완료 상태로 관리한다. 접수 저장 성공 후에만 완료 메시지를 보여주고, 알림 실패는 저장 실패와 구분해 재처리한다. 문의가 DB 또는 승인된 접수 저장소에 남는지 확인하여 알림 메일만으로 접수 여부를 판단하지 않는다.

일반 문의의 1차 답변 목표는 영업일 1일 이내로 제안한다. 맞춤 가공·견적은 담당자가 확인할 항목과 예상 회신 시점을 알린다. 이 목표를 운영 시간과 인력 검토 없이 외부 보장으로 게시하지 않는다.

### 샘플과 거래 전환

샘플 운영은 현재 승인된 품목·비용·배송·제공 조건을 확인한 뒤 진행한다. 접수 정보 확인, 조건 안내, 대상 승인, 발송 기록, 고객 사용일 이후 의견 수집, 적합 제품 제안, 첫 주문과 재주문 확인 순으로 관리한다.

무료 샘플·무료배송·할인을 과거 행사에서 자동 승계하지 않는다. 후속 연락과 안내 발송은 고객 동의 및 현재 승인된 운영 절차 안에서 담당자가 진행한다. 계획서 작성은 고객 연락을 실행하는 지시가 아니다. 샘플 원가·포장·배송·응대 시간을 기록하고 긍정적 후기 작성을 혜택 조건으로 삼지 않는다.

### 기존 주소 이전

기존 jaban의 상품·분류·게시글·회원·주문·이미지·첨부 주소를 수집한다. 각 주소는 새 jaban 콘텐츠, 해당 gorebob 상품·기능, 유지해야 하는 자산, 종료 주소로 나눈다. 임의로 모두 새 홈으로 이동시키지 않는다.

기존 상품번호와 새 상품 연결, 필요한 쿼리, 인증 흐름을 확인하고 적절한 서버측 영구 리디렉션을 구성한다. 대응 콘텐츠가 없는 종료 주소는 적절한 404·410 처리를 검토한다. 민감한 인증 값이나 주문정보는 공개 이동 URL에 덧붙이지 않는다. Google은 기존 URL과 새 URL 매핑 및 리디렉션 검증을 안내하며, 리디렉션은 가능한 오래, 일반적으로 최소 1년 유지하도록 권고한다. [Google 사이트 이전 공식 안내](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)

jaban 루트는 콘텐츠로 남고 일부 쇼핑 경로만 gorebob으로 옮겨질 수 있으므로, 전체 도메인 이전을 전제로 한 검색 도구의 주소 변경 기능을 일괄 적용하지 않는다. 실제 이전 범위를 먼저 확인한다.

### 전환과 복구 순서

1. 시험 환경을 최종 검토하고 현재 파일·DB·업로드·스킨·DNS 기록을 보존한다.
2. DNS에서 웹·메일·서브도메인·확인용 TXT 등 영향을 받는 항목을 구분한다. 회사 메일 설정을 유지한다.
3. 운영 담당, 지원 연락처, 변경 시간, 중단·복구 기준을 정하고 운영 전환 지시를 확인한다.
4. jaban 전환과 gorebob 스킨 변경을 가능한 별도 작업으로 시행한다. 각 작업 직후 링크·메일·구매를 확인한다.
5. 공개할 페이지의 검색 제외 설정을 해제하고 필요한 사이트맵·대표 URL을 확인한다. 시험 환경은 접근 제한을 유지한다.
6. 첫 48시간은 링크·메일·문의·구매 오류를 집중 확인하고 이후 2주 동안 유입·404·CS를 점검한다.

결제·로그인·메일·문의가 주요 고객 흐름에서 실패하면 해당 변경을 중단하고 검증된 이전 스킨 또는 웹 연결로 복구한다. DNS 복구에는 전파 지연이 있을 수 있으므로 즉시 복구를 보장하지 않는다. gorebob 주문 DB를 jaban 복구와 함께 과거 시점으로 되돌리지 않는다. 워드프레스 복원에서도 복원 시점 이후 문의·콘텐츠의 보존·재반영 방법을 확인한다.

초기 발행량은 월 신규 가이드·FAQ 4개, 설명 영상 1~2개, 짧은 영상 2~4개로 제안한다. 촬영 자산과 편집 인력이 부족하면 글·사진 중심으로 줄인다. 주 6시간 안에 촬영·편집까지 가능하다고 가정하지 않는다.

매월 첫 주에는 질문·상품 변경·성과를 검토하고, 둘째 주에는 촬영과 초안을 준비하며, 셋째 주에는 검수·발행, 넷째 주에는 상담 후속과 다음 주제를 정한다. 자료·제품 변경은 월간 일정을 기다리지 않고 수정한다.

장애 신고는 운영 담당이 접수하고 구매 장애·권한 문제는 개발 담당에게 즉시 전달하는 내부 목표를 둔다. 응급 수정 후 변경 내용과 결과를 기록한다. 업데이트는 시험 환경에서 주요 화면과 폼을 확인한 후 적용하고, 담당자 부재 시 대체 담당과 연락 경로를 마련한다.

## 15 유입과 성과 측정

검색 유입은 고객 질문에 직접 답하는 글과 실제 제품 가이드를 중심으로 늘린다. 제목·설명·내부 링크·이미지 설명을 정리하고 두 사이트의 검색 등록·사이트맵을 검토한다. 레시피와 영상은 확인된 내용만 게시하며 검색 노출 순위를 보장하지 않는다.

유튜브에서는 설명을 원하는 고객에게 jaban 글을, 구매 목적이 분명한 고객에게 gorebob 상품을 연결한다. 인쇄물·QR·공개 안내의 링크를 연결표에 포함한다. 유료 광고는 측정·상품·문의 동선 검증 후 예산을 별도로 정하며 이번 계획에서 집행하지 않는다.

### 측정 구현

두 사이트가 같은 분석 운영 체계로 측정될 수 있는지 접근 권한과 태그 설치 범위를 확인한다. GA4 교차 도메인 측정은 같은 웹 데이터 스트림의 동일한 태그 ID를 사용하는 구성과 `_gl` 전달 검증이 필요하다. 자동 외부 링크 클릭 집계가 달라질 수 있으므로 상품 연결 클릭은 별도 이벤트로 확인한다. [GA4 교차 도메인 공식 안내](https://support.google.com/analytics/answer/10071811?hl=ko)

이 설정은 구매 회원·로그인·장바구니 공유를 뜻하지 않는다. 내부 이동에 새로운 캠페인 태그를 붙여 최초 유입 출처를 덮어쓰지 않는다. 수집·동의 설정과 차단에 따른 누락을 보고서에 표시하고, 교차 도메인 추적이 검증되지 않으면 클릭 수와 쇼핑몰 주문 수를 별도로 보고한다.

| 지표 | 정의 | 초기 판단 기준 제안 |
|---|---|---|
| 콘텐츠에서 상품 이동 | 상품 연결 클릭 ÷ 해당 콘텐츠 조회 | 첫 4주 기준선을 만든 뒤 주제별 비교 |
| 유효 문의 | 실제 제품·거래 문의 수, 문의 제출 실패 수 | 문의 수와 오류·응답 시간을 함께 확인 |
| 첫 응대 시간 | 접수에서 1차 사람 응답까지의 영업시간 | 영업일 1일 이내 목표의 달성 여부 |
| 구매 준비 시간 | 로그인 이후 동일 상품·수량 선택 시작부터 장바구니 확인까지 | 시험 고객 5~8곳의 중앙값·실패 사례 비교. P1 후 30% 감소를 내부 목표로 제안 |
| 상품·수량 오류 | 잘못 선택한 상품·옵션·개수의 과제 및 관련 CS | 기능 개선 후 증가하지 않는지 확인 |
| 문의·샘플 전환 | 관찰 30일을 채운 고객 중 첫 주문 고객 비율 | 비용·관찰기간·고객군과 함께 보고 |
| 재구매 | 첫 주문 이후 60일 관찰이 가능한 고객 중 재주문 비율 | 관찰기간 미충족 고객을 분모에서 제외 |
| 경제성과 | 관련 매출·기여이익·운영 시간·추가 비용 | 주문 근거와 측정 누락을 명시해 비교 |

제안 이벤트는 `product_link_click`, `resource_download`, `inquiry_submit`, 후속 단계의 `calculator_complete`, `quick_order_start`이며 기존 `add_to_cart`·`purchase` 구현과 중복되지 않게 정한다. 문의는 저장 성공 시 제출로 집계한다. 결제 이벤트는 실제 주문 상태와 대조하고 취소·반품을 조정한다. 연락처·이메일·문의 본문·고객 원본 주문번호를 분석 이벤트에 넣지 않는다.

구매 연결 기여와 전체 매출 증가는 구분한다. 광고·가격·계절·기존 영업활동의 영향을 함께 기록하며, 측정 가능한 주문만 두 사이트 연결 성과로 집계한다. 매출·고객 상세 보고는 비공개 운영 체계에서 관리하고 저장소에는 정의·산식·비식별 요약만 둔다.

## 16 비용과 투입 산정

총 구축비를 확정하려면 스킨 변경 범위, 기존 기능의 재사용성, 콘텐츠 원본, 개발 담당의 단가·가용시간이 필요하다. 아래 투입량은 계획용 추정이며 견적이나 완료 약속이 아니다. 1인일은 구현 담당 8시간 기준으로 가정하고 AI 도구 사용만으로 같은 기간이 보장된다고 보지 않는다.

| P0 작업 | 구현·기술 검토 투입 제안 | 산정 조건 |
|---|---|---|
| 현황 조사·구조·호스팅 적합성 | 3~5인일 | 읽기 권한과 원본 자료 확보 |
| 공통 디자인·워드프레스 테마·편집 양식 | 7~10인일 | 맞춤 대형 페이지 빌더 없이 기본 편집 중심 |
| 콘텐츠 입력 지원·문의·구매 링크 | 4~6인일 | 원고·사진 제공, 별도 복잡한 회원 기능 없음 |
| gorebob 스킨 개선 | 4~7인일 | 구매 엔진 교체 없이 기존 스킨과 기능 활용 |
| 통합·이전·측정·복원·문서 | 5~8인일 | 시험 환경과 필요한 설정 권한 확보 |
| 합계 | 23~36인일 | 촬영·원고 작성·법정 문구 검토·대기 시간·P1 제외 |

총괄·제조·영업의 검토 시간과 콘텐츠 원고·촬영·편집 시간을 별도로 잡는다. 변경과 재작업에 대한 여유분은 추정 구축비의 15~20%로 제안한다. 상한과 포함 범위를 견적 검토 시 정한다. 구현 가용시간이 주 2~3일이면 P0 공개 목표를 그에 맞게 늦춘다.

| 비용 묶음 | 예산에 포함할 항목 | 확정 방법 |
|---|---|---|
| 초기 제작 | 인일×단가, 디자인, 원고, 사진·영상, 이전·검증 | 작업 범위별 견적 또는 내부 시간 기록 |
| 정기 인프라 | 호스팅, 도메인 갱신, 외부 백업, 필요한 라이선스 | 실제 계약 주기·요금 확인 |
| 정기 운영 | 콘텐츠·품질 검토·CS·유지보수 인건비 | 역할별 실제 시간×내부 비용 기준 |
| 선택 서비스 | 메일, 분석, AI API, 파일 저장, 편집 서비스 | 무료 범위·상한·사용량 확인 후 선택 |
| 고객 개발 | 샘플 원가·포장·배송·추가 응대·광고 | 현재 승인 조건과 별도 실행 예산 |

P1은 P0 추정에 포함하지 않는다. 계산기, 빠른 발주, 저장 목록마다 지원 옵션·권한·기존 코드 재사용 여부를 조사한 후 별도 산정한다.

경제성은 추가 매출에서 해당 제품원가·변동 출고비·수수료·할인·샘플 비용을 차감한 기여이익을 기준으로 검토한다. 추가 운영·유지보수비를 다시 차감해 월 순효과를 계산하며, 순효과가 양수일 때만 초기 구축비를 월 순효과로 나눈 단순 회수기간을 참고한다. 효과를 확인하지 않은 상태에서 회수기간을 제시하지 않는다.

## 17 주요 위험과 확장 판단

| 위험 | 발생 시 영향 | 계획상 대응 |
|---|---|---|
| 두 사이트 상품정보 불일치 | 고객 혼란·잘못된 구매량 | 카페24 원본 유지, P0 가격 복제 배제, 구매 전 재검증 |
| 인증·제품 표현의 근거 부족 | 신뢰 저하·오해 | 근거·담당·유효기간을 기록하고 확인 전 공개 보류 |
| 호스팅 기능·권한 부족 | 문의·API·이전 기능 구현 지연 | 계약 전 시험·확인, P0 링크 연결로 범위 축소 가능 |
| DNS·이미지·메일 단절 | 기존 고객 접근·회사 업무 영향 | 전체 주소·메일 목록, 별도 전환, 복구 연습 |
| 기존 구매 기능 회귀 | 로그인·주문·결제 실패 | 복제 스킨·기존 흐름 대조, 중대한 실패 시 변경 복구 |
| 콘텐츠·상담 시간 초과 | 방치된 문의와 오래된 정보 | 4주 시간 기록, 발행량 조정, 대체 담당 확보 |
| 분석 누락·중복 | 과장된 성과 판단 | 이벤트·주문 대조, 추적 불가 구간 명시 |
| 개인정보·구매 자료 노출 | 고객 정보 유출 | 비공개 저장·최소 권한·본인 확인·분리된 공개자료 |

회원형 커뮤니티는 공개 FAQ·편집형 사용 사례 운영 후 검토한다. 판단안은 2개월 연속 월 실제 질문·사례 10건 이상, 반복 참여 고객 5곳 이상, 응대·관리 시간 확보이며 수치는 제안이다. 조건이 충족되어도 먼저 운영 규칙·가입 이유·비공개 문의 경계를 정한다.

AI 식단표·자연어 발주는 표준 상품·옵션 매칭과 수량 규칙이 안정된 후 시험한다. 첫 결과는 검토용 발주 초안으로 제공하고 고객 검토 없이 주문·결제를 제출하지 않는다. 영양 식단·질환식 처방이나 최저 예산 보장은 별도 전문 검증 없이 제공하지 않는다.

## 18 착수 전에 확정할 항목

1. P0 메뉴·화면 범위와 초기 콘텐츠 목록, 공개할 원본 자료 및 사진 권한.
2. 실제 상품·옵션·판매 단위와 기존 주문·재주문·자료 기능의 확인 담당.
3. 워드프레스 호스팅 후보, 시험 환경, 문의 저장·알림 방식, 경로별 이전 가능 여부.
4. 운영 총괄·콘텐츠·품질·영업·개발의 담당과 대체 담당, 주간 가용시간.
5. 제작비 산정 기준, 정기 비용 상한, P1 별도 산정 원칙.
6. 사용성 확인 고객군, 성과 기준선, 착수일과 공개 목표일.
7. 기존 DNS·메일·이미지·콜백·사업체 표기의 확인 담당과 전환·복구 기준.

위 항목은 계획을 구체화하기 위한 결정 목록이다. 계획서 검토와 호스팅 계약·DNS 변경·운영 배포·고객 연락의 실행 지시는 구분한다. 문서가 승인되면 실제 확정한 항목만 `docs/decisions.md`에 기록하고, 구현·검증 결과는 `docs/status.md`에 남긴다.
