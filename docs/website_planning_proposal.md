# jaban.co.kr 초안 제작 계획 v3.0

작성일: 2026-10-04 (Asia/Seoul). 상태: 로컬 제작을 위한 제안. 범위: 정보 구조·사용 동선·화면·콘텐츠·검수·시험 적용 계획. 서버 변경과 공개는 미실행.

## 1. 제작 목적과 성공의 정의

jaban.co.kr은 고객이 “어떤 회사인지, 내 용도에 어떤 제품이 맞는지, 구매 전 무엇을 확인해야 하는지”를 이해하도록 돕는다. 회사 소개를 읽는 것에 그치지 않고 제품 선택·조리 자료·상담·gorebob.com 구매로 이어지는 안내 사이트로 만든다.

첫 공개의 우선순위는 ① 제품 선택을 돕는 정보 ② 근거가 있는 제조·품질 설명 ③ 조리·사용 지원 ④ 적절한 구매 또는 문의 연결이다. 기존 구매 고객은 쇼핑몰로 바로 이동할 수 있어야 한다. 두 사이트의 회원·장바구니 통합, 실시간 가격·재고 표시, 계산기, 빠른 발주, 커뮤니티는 이번 초안에 포함하지 않는다.

성공 기준은 방문자가 사이트 설명 없이 제품 가이드·품질 자료·문의·쇼핑몰을 찾고, 연결되는 상품과 설명의 차이를 이해하는 것이다. 공개 전 사용 과제를 검증하고 공개 후 유입·상품 이동·문의의 기준선을 측정한다. 클릭을 실제 구매로 간주하지 않는다.

## 2. 고객별 과제와 핵심 동선

| 고객·상황 | 가장 먼저 해결할 질문 | 시작 화면과 동선 | 도착점 |
|---|---|---|---|
| 급식 구매 담당·영양사 | 가공 형태·규격·가시 안내가 우리 조리에 맞는가 | 홈 → 제품 선택 가이드 → 어종 상세 → 규격 확인 | 일치하는 쇼핑몰 상품 또는 상담 |
| 식당·외식업 신규 고객 | 원하는 메뉴·포장 단위·손질 방식이 있는가 | 가이드 → 가공 형태·조리 용도 설명 → 관련 상품 | 상품 옵션 확인 또는 맞춤 문의 |
| 품질을 확인하는 거래 담당 | 제조 주체·시설·인증을 확인할 수 있는가 | 제조·품질 → 근거 자료 → 회사 소개/문의 | 공개 가능한 인증 자료 또는 자료 요청 채널 |
| 가정용 신규 고객 | 손질·조리·보관 방법과 구매 위치는 어디인가 | 레시피 → 사용 제품 설명 → 상품 | 쇼핑몰 상세 |
| 기존 구매 고객 | 어디서 바로 주문하는가 | 모든 화면의 쇼핑몰 버튼 | gorebob.com |
| 구매 후 고객 | 산 제품을 어떻게 조리하고 어디에 문의하는가 | 레시피·고객지원 → 관련 안내 | 조리 자료 또는 기존 고객지원 |

고객군별 별도 사이트를 만들지 않는다. 공통 제품 정보를 재사용하고 용도·가공 형태·조리법으로 탐색하도록 한다. 정보량이 적은 초기에는 복잡한 검색·필터보다 명확한 목록과 연결을 우선한다.

## 4. 정보 구조와 초기 화면 범위

주 메뉴: **제품 선택 가이드 / 제조·품질 / 레시피·활용 / 회사 소개 / 고객지원**. 공통 구매 버튼: **고래밥몰에서 구매**. 브랜드 로고는 홈으로 연결한다.

| 화면 | 제안 주소 | 방문자에게 제공할 답 | 필수 구성 |

| 가이드 목록 | /guides/ | 어떤 어종·가공 형태부터 확인할까 | 어종 카드, 가공 형태 읽는 법, 구매 전 확인 항목 |

“5대 페이지”는 다섯 콘텐츠 영역으로 해석한다. 홈·목록·상세를 포함한 실제 화면 수는 별도로 관리한다. 초안은 홈 1, 가이드 목록 1, 어종 상세 1, 품질 1, 레시피 목록 1, 레시피 상세 1, 회사 1, 고객지원 1의 **8개 대표 화면**을 제작한다. 네 어종은 동일 템플릿을 재사용하며 검수된 어종부터 채운다. /contact/ 등 기존 주소와의 관계는 이전 주소 목록 확보 후 정한다.

## 5. 화면별 제작 상세

### 홈

첫 화면은 제품 선택과 바로 구매의 두 행동을 제시한다. 제목 초안은 “용도에 맞는 수산물 선택과 조리 정보를 안내합니다.”로 두고 브랜드 표현은 검토 후 조정한다. 검증되지 않은 업력·최상급 표현은 쓰지 않는다.

순서: 간결한 소개와 가이드/구매 버튼 → 어종 가이드 카드 → 제조·품질 근거 요약 → 레시피 → 상담 안내. 긴 회사 연혁, 자동재생 영상, 대형 슬라이드로 첫 행동을 가리지 않는다. 화면 내 주된 버튼과 보조 버튼의 우선순위를 명확히 한다.

### 제품 선택 가이드

목록에서 어종명과 가공 형태를 먼저 읽을 수 있게 한다. 초기 후보는 고등어·삼치·임연수·갈치이며, 공급 안정성·실제 판매 여부·자료 준비도를 확인해 확정한다. 미확인 규격으로 선택 필터를 만들지 않는다.

상세 순서: 한 줄 용도 설명 → 확인된 제품 사진 → 가공 형태 → 판매 단위·옵션 읽는 법 → 제품별 가시 주의사항 → 관련 조리법 → 실제 상품 확인. 인분·정량 계산은 초기 제외하고 필요 중량 판단 시 판매 단위·해동 전후 기준 등을 확인하도록 안내한다.

구매 버튼은 “고래밥몰에서 규격·가격 확인”으로 표시한다. 여러 상품이 관련되면 규격 차이가 보이는 선택 목록을 제공한다. 미확인 링크는 초안에서 작동시키지 않고 검수 대기 상태를 표시한다. 품절·판매 중단 시 안내와 확인된 카테고리/문의 동선을 제공하며 다른 규격을 동일 상품처럼 대체하지 않는다.

### 제조·품질

공정 순서와 장비는 현장 검수 후 넣는다. 초안은 공정 카드·사진·설명·근거 자료 영역만 만든다. 인증은 대상 사업체·사업장·품목·유효기간이 확인된 범위로 표현한다. 인증서의 개인정보·서명 등 공개 범위를 검수한 사본을 사용한다. 스캔 이미지 외에 핵심 내용을 텍스트로 제공하고 다운로드 파일의 종류·용량·기준일을 표시한다.

### 레시피·활용

목록은 조리 방식·사용 어종이 드러나는 제목과 사진으로 구성한다. 상세에는 사용 제품 조건, 재료·분량 기준, 장비, 과정, 확인된 주의사항, 관련 가이드와 상품 연결을 둔다. 가정용과 대량 조리 조건을 구분한다. 확인되지 않은 온도·시간·수율·안전 수치를 생성하지 않는다. 영상은 클릭 재생과 텍스트 요약을 제공하며 영상 없이도 핵심 정보를 이해할 수 있게 한다.

### 회사 소개와 고객지원

회사 소개는 제조·유통 역할을 먼저 설명하고 검증된 역사·사진을 추가한다. 고객지원은 제품 선택/대량 거래, 기존 주문·배송, 제품 불편 문의를 구분한다. 주문 문의는 쇼핑몰의 본인 확인 가능한 채널로 연결한다. 공개 게시물이나 분석 이벤트로 고객 주문·연락처를 받지 않는다. 미확인 이메일·전화·운영시간은 자리표시자로 유지한다. 문의 폼과 샘플 신청은 후속 과제다.

## 6. 공통 사용성·디자인 기준

- 모바일을 먼저 설계하고 360·390·768·1280px에서 확인한다. 본문 기본 16px, 주요 터치 영역 44~48px를 초안 목표로 두되 실제 기기에서 사용성을 확인한다.
- 메뉴는 고객이 이해하는 이름을 사용한다. 모바일 메뉴는 열기·닫기·키보드 이동이 가능하고 구매 버튼이 본문을 가리지 않게 한다.
- 링크와 버튼을 구분하고 키보드 초점, 제목 순서, 이미지 대체 설명, 충분한 명암을 검수한다. 색만으로 검수 상태나 선택 여부를 전달하지 않는다.
- 외부 쇼핑몰 이동을 문구로 알린다. 기본은 같은 탭 이동으로 계획하고, 뒤로 가기 시 목록·선택 상태가 유지되는지 확인한다.
- 실제 공장·제품 사진을 우선한다. 미확인 실사 대신 중립적인 자리표시자를 사용한다. 생성 이미지를 실제 제조시설·제품 증빙처럼 제시하지 않는다.
- 카드 전체에 중복 링크를 난립시키지 않는다. 각 영역은 다음 행동이 분명해야 한다. 긴 자료에는 요약과 목차를 둔다.
- 공통 머리말·꼬리말·카드·주의문·자료 다운로드·빈 상태·오류 상태를 재사용한다. 문구 수정이 전체 화면에 일관되게 반영되도록 한다.

| 레시피 | 원본 URL·사용권·조건·본문·사진 | 콘텐츠 작성 / 조리 내용 검수 | 출처·재현 조건·주의사항 확인 |
| 지원 | 문의 목적·URL·전화·메일·시간·응대 주체 | 콘텐츠 작성 / CS 검수 | 실제 채널과 담당 확인 |

역할은 제안이며 실제 담당자·대체 담당·검수 날짜는 배정 후 입력한다. 각 자료에는 `항목 ID / 출처 / 확인일 / 검수자 / 상태 / 다음 확인일`을 기록한다. 상품 연결에는 원본 시스템 식별자, 공개 URL, 제품 조건, 판매 상태, 대체 동선, 마지막 검증일을 추가한다. 숫자를 임의로 채우지 않는다.

초안의 샘플은 “검수 대기”로 명시한다. 미확인 콘텐츠는 공개 빌드에서 제외하고, 실제 정보처럼 보이는 허구의 중량·가격·인증번호를 쓰지 않는다.

## 8. 제작 단계와 산출물

| 단계 | 작업·시작 조건 | 산출물 | 종료 기준 |
|---|---|---|---|
| D0 구조 확정 | 현재 문서·자료 확인, 로컬에서 시작 | 사이트맵·고객 과제·콘텐츠/상품 확인 목록 | 8개 대표 화면과 제외 범위가 정리됨 |
| D1 와이어프레임 | D0 완료 | 모바일·데스크톱 저해상도 화면, 주요 동선 | 가이드·품질·지원·구매를 찾는 경로 확인 |
| D2 로컬 초안 | D1 검토 반영 | 공통 스타일·8개 대표 화면·네 어종용 데이터 양식 | 주요 이동·빈 상태·한국어 표시가 로컬에서 작동 |
| D3 사실·사용성 검수 | D2 및 담당 확인 가능 자료 | 검수표·상품 매핑표·과제 결과·수정 목록 | 중대한 정보 오류·길 찾기 실패 수정 |
| D4 제한된 시험 서버 적용 | 별도 적용 지시, 백업과 접근 제한 검증 | 워드프레스 템플릿·시험 콘텐츠·설정/복원 기록 | 편집·권한·미디어·기기·복원 시험 통과 |
| D5 공개 준비 | 자료 검수 및 시험 완료 | 주소 이전표·DNS/메일 기준·공개/복구 체크리스트 | 도메인·메일·상품·연락·SSL 검증 후 공개 결정 |

D0~D3은 서버 설정·DNS 변경 없이 진행한다. D2는 워드프레스에 옮길 수 있는 구성 요소와 콘텐츠 양식으로 설계하되 로컬 HTML/CSS 미리보기부터 만들 수 있다. 최종 테마 방식은 기존 테마·편집 기능 확인 후 정한다. 대형 페이지 빌더·유료 테마 선택을 착수 조건으로 만들지 않는다.

작업량은 대표 화면 8종과 공통 요소를 기준으로 추적한다. 우선 공통 요소·홈·어종 상세를 검토한 뒤 나머지 화면을 확장한다. 달력 일정은 제작 담당 가용시간과 자료 준비표 확인 후 산정한다. 자료 대기는 레이아웃 제작을 막지 않으며 공개 콘텐츠는 준비된 범위로 조정한다.

## 9. 초안 사용성 검증

내부 역할 대행 검토 후 가능하면 실제 고객군 3~5명의 검토를 진행한다. 고객 연락은 별도 지시에 따른다. 내부 시험만 수행한 경우 고객 검증 완료로 기록하지 않는다.

| 과제 | 관찰할 내용 | 초안 통과 기준 제안 |
|---|---|---|
| 원하는 어종의 규격·가시 안내 찾기 | 메뉴 이해·길 찾기·표기 오해 | 안내 없이 해당 설명 도달, 불확실한 항목 인지 |
| 가이드에서 구매할 상품 확인 | 외부 이동 이해·상품 조건 일치 | 상품·규격을 혼동하지 않고 올바른 연결 선택 |
| 제조 주체와 인증 확인 | 증빙의 위치·적용 범위 이해 | 회사 관계와 인증 적용 범위를 구별 |
| 레시피에서 관련 제품 찾기 | 영상 의존·조리 조건 해석 | 텍스트로 조건 파악, 관련 가이드 도달 |
| 주문 문의 채널 찾기 | 신규 상담과 주문 CS 혼동 | 적절한 기존 채널 선택 |
| 구매 고객의 쇼핑몰 바로가기 | 첫 화면·모바일 메뉴 | 불필요한 가이드 경유 없이 이동 |

참여자 역할·기기·성공/실패·소요시간·오해·개선 조치를 기록한다. 작은 표본의 결과를 전체 고객 전환율로 해석하지 않는다. 잘못된 상품 연결, 문의 채널 단절, 모바일 메뉴 사용 불가, 검수 대기 사실의 공개를 우선 수정한다.

## 10. 시험 환경과 공개 조건

로컬 제작은 호스팅 접속이나 noindex 설정을 기다리지 않는다. 서버 적용은 별도 단계이며 임시 도메인도 외부에서 접근할 수 있다.

검색 노출 제한과 접근 제한은 다르다. 워드프레스 검색 노출 설정만으로 비공개가 되지 않는다. 비공개 시험은 인증 등 접근 제한을 적용하고, 로그아웃·새 세션에서 페이지와 직접 미디어 URL까지 확인한다. 지원 여부가 불명확하면 로컬 검토를 유지한다. [WordPress 공식 설명](https://core.trac.wordpress.org/changeset/49287)

robots.txt 차단만으로 검색 제외를 보장하지 않는다. 크롤링을 막으면 검색엔진이 noindex를 읽지 못할 수 있으므로 검색 제외 정책을 접근 정책과 구분해 확인한다. [Google 공식 안내](https://developers.google.com/search/docs/crawling-indexing/block-indexing)

공개 전 필수 확인:

1. 모든 공개 문구의 근거·검수·적용 범위와 사진 사용권 확인.
2. 상품 링크·옵션·가시 안내 일치, 품절·삭제 시 대체 동선 확인.
3. 모바일·키보드·한국어·링크·다운로드·연락 채널 검증. 시험 통화·메시지는 별도 지시에 따라 수행.
4. 정식 도메인 인증서·HTTPS 이동·이미지/스크립트 로딩 확인.
5. 기존 URL별 유지/이전/종료 목록과 필요한 리디렉션 검증. 구매·미디어·콜백 주소 영향 조사.
6. 현재 DNS 전체 기록 보관, 웹 연결 변경과 MX·TXT·메일 설정 영향 확인. 변경 전후 메일 시험은 별도 실행 범위로 관리.
7. 파일·DB·설정 백업과 시험 환경 복원 확인. 복원 위치·담당·실측 시간을 기록하며 임의 복구시간을 보장하지 않음.
8. 페이지 제목·설명·정식 URL·사이트맵·분석 이벤트 확인. 정식 사이트만 검색 노출 허용하고 시험 사이트 제한 유지.

단계별 통과 기록이 있어야 공개를 결정한다. 현재 계획 작성은 이 검증을 완료한 것으로 간주하지 않는다.

## 11. 공개 이후 운영과 측정

상품 링크·판매 상태는 공개 전과 상품 변경 시 확인하고 초기에는 주 1회 검토한다. 인증·공정·연락처는 원본 변경 시 재검수한다. 담당 변경·링크 장애·판매 중단 시 해당 안내를 수정하거나 비공개 처리한다.

첫 30일은 방문·가이드 조회·상품 이동 클릭·지원 채널 클릭을 측정해 기준선을 만든다. 클릭과 실제 문의를 구분하고 문의 기록은 담당의 비식별 집계로 보완한다. 결제 기여는 쇼핑몰 측정과 검증 가능한 연결이 있을 때만 보고한다. 분석 데이터에 연락처·문의 본문·주문 원본 식별자를 넣지 않는다.

후속 개발은 실제 문제에 따라 결정한다. 규격·수량 문의가 반복되면 계산기, 재발주 불편이 확인되면 빠른 발주, 기존 문의 채널로 관리가 어려울 때만 접수 폼을 검토한다. 기능 수보다 고객 과제 해결과 운영 가능성을 우선한다.

## 12. 이번 계획의 완료 범위와 다음 산출물

이번 개정은 제작 목적·고객 동선·8개 대표 화면·콘텐츠 검수·로컬 제작·시험 적용·공개 조건을 정리한 문서 작업이다. 실제 템플릿, 서버 설정, 상품 실측, 고객 시험, 공개는 아직 수행하지 않았다.

다음 제작 산출물은 **모바일 우선 와이어프레임 8종, 공통 구성 요소 목록, 콘텐츠 준비표, 상품 연결표, 로컬 클릭 미리보기와 검수 기록**이다. 먼저 홈·어종 상세·공통 메뉴의 동선을 검토하고 같은 기준으로 나머지 화면을 제작한다.
