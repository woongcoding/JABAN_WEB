## 워드프레스 관리자 상태 확인 (2026-10-03)

사용자가 관리자 페이지의 상태 확인을 요청하여 `.env`의 워드프레스 계정으로 로그인했다. 관리자 대시보드와 일반 설정, 읽기 설정, 플러그인, 테마, 사이트 건강의 정보 화면이 모두 HTTP 200으로 응답했다. 계정·비밀번호·쿠키는 기록하지 않았다.

|---|---|
| 접속 주소 | `https://sh8945.mycafe24.com/wp-admin/` |
| WordPress / PHP | 7.1.2 / 8.4.21p1, 웹 서버 Apache |
| 활성 테마 | Twenty Twenty-Five (2025) |
| 콘텐츠 | 공개 글 1개, 공개 페이지 1개, 댓글 1개, 검토 중 댓글 0개 |
| 사이트 / 워드프레스 주소 설정 | 모두 `http://sh8945.mycafe24.com`으로 저장되어 있음. HTTPS 접속 자체는 성공 |

활성 플러그인은 Disable XML-RPC-API, Login Lockdown, NinjaFirewall (WP Edition), Two Factor, WP 슈퍼 캐시였다. Really Simple Security는 설치되어 있지만 비활성 상태였다. 업데이트 알림은 화면 관찰값이며 호환성·취약점 검증 결과가 아니다.

### 관리자 403 재현과 접속 결과

- 기본 자동화 브라우저의 관리자·로그인 주소 요청에서 `NinjaFirewall 403 Forbidden`을 확인했다.
- 같은 로그인 주소에 일반 Chrome 식별값을 보낸 요청은 HTTP 200과 로그인 폼을, HeadlessChrome 식별값을 보낸 요청은 HTTP 403을 반환했다. 이번 403은 자동화 클라이언트 식별값에 따라 재현되는 차단으로 확인했으며 해외 IP 제한이나 계정 오류로 단정하지 않는다.
- 설치된 Chrome 버전의 일반 데스크톱 식별값을 사용한 새 브라우저 세션에서 관리자 로그인과 화면 조회에 성공했다. 방화벽 비활성화·접속 허용 목록 변경·디렉토리 제한 해제는 수행하지 않았다.
- [카페24 공식 관리자 접속 안내](https://help.cafe24.com/faq/wordpress/managed-wordpress/connection-error/wordpress_admin_forbidden_overseas/)는 별도의 국내 IP 기본 제한 정책을 설명한다. 해당 일반 정책만으로 이번 NinjaFirewall 차단 원인을 판단하지 않았다.

이번 작업은 조회만 수행했다. HTTP 주소 설정, 한국 시간대 적용, 개발 중 검색엔진 수집 제한, 업데이트는 이후 설정 범위를 확정해 처리할 항목이다. 건강 진단 전체, 메일 발송, 백업 복원, 실제 구매와 연동은 아직 검증하지 않았다. 재현 스크립트와 민감값을 가린 조회 결과는 Git 제외 대상 `private/wp-admin-readonly-inspector.py`, `private/wp-admin-observed.json`에 보관했고 조회 세션은 종료했다.

## 워드프레스 구축 전 남은 확인

1. 신규 워드프레스 개설과 관리자 접속은 확인했다. 계약 상품의 세부 결제 조건·용량·트래픽은 해당 서비스 관리 화면에서 추가 확인한다. 앞서 조회한 기존 계정 목록의 미확인 결과와 구분한다.
2. PHP·워드프레스 버전은 위 관리자 관찰값으로 확인했다. 테마·플러그인 설치 동작, SFTP/SSH, 외부 서버 호출, 문의 저장·메일 발송, 경로별 리디렉션 범위는 별도 검증한다.
3. 스테이징·SSL·자동 백업·복원·별도 백업의 실제 이용 조건을 확인한다. 이번에 조회한 구형 호스팅이나 웹메일 조건을 새 워드프레스 상품에 적용하지 않는다.
4. 기존 쇼핑몰의 대표 도메인·이미지·로그인·결제 복귀·서류 연결과 회사 메일을 별도로 검증한다.
5. 전환 전에 전체 DNS와 기존 파일·설정의 복구 자료를 확보한다. 현재의 부분 DNS 기록을 완료된 백업으로 취급하지 않는다.
